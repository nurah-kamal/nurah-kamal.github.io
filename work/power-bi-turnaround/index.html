The question

SA Turnaround showed that counting calendar days blames a service desk for public holidays. A finding like that only helps if the people filtering a report all see the same, correct figure. So: can a Power BI model count turnaround in South African working days, and can it be shown to agree with the SQL?

What I built and found

Four report pages on one model. The finding holds: with holidays counted, one real problem is left, refunds, which went from 16.1% late to over 50% after a second sign-off step.

The headline page agrees with SA Turnaround exactly: 5,706 closed requests, 1,183 late by calendar days, 1,060 late by working days, 283 wrongly called late and 160 late but missed.

How I checked it

  • Working days are a subtraction, not a loop. The date table carries a running count of working days, so working days between two dates is the count on the closing day minus the count on the opening day.
  • The holidays come from code, not a typed list. The date table is written by the same tested library as the SQL project: the twelve statutory days, Easter, the Sunday rule and each declared day with its source.
  • Checked against an independent answer. The measures were checked by DAX query against figures worked out in plain code from the same data: every headline figure, all 12 refund quarters and the three holiday windows match exactly.
  • Readable in a diff. Saved as a .pbip, so the model is TMDL text and each visual is its own JSON file. A change to one chart is a small, reviewable change.
  • No person is in the data. Not a real one and not a made-up one.

The principle behind it

Model the data once, so everyone filtering a report sees the same, correct figure.

A dashboard is only as trustworthy as the model under it. Here the model is tested against a second, independent answer before any page is drawn.

Worth knowing

  • The data is synthetic. It shows the method, not any real organisation’s performance.
  • You need Power BI Desktop (free, Windows) to open the report; the repository README walks through pointing the model at the data.
  • The date table covers 2023 to 2025, every date in the data.
